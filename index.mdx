<section className="ct-section" aria-labelledby="ct-what">
  <div className="ct-wrap ct-prose">
    <h2 id="ct-what">What it does</h2>
    <p className="ct-lead"><strong>The model guesses. CTRLRun does not.</strong> The ticket says refund €500. The agent asks for €5,000, one extra zero. The tool is in its list, the arguments are well formed, and the model is completely confident. Nothing above the call disagrees, because nothing above the call is a check: a tool being callable is not permission to call it with those arguments.</p>
    <div className="ct-compare">
      <div><span className="ct-compare-label">Without CTRLRun</span><p>Nothing checks the amount. The call goes through. <strong>€4,500 too much.</strong></p></div>
      <div><span className="ct-compare-label">With CTRLRun</span><p>Your rule checks the amount. The call never leaves. <strong>€0 wrongly paid.</strong></p></div>
    </div>
    <p>CTRLRun is that check. It reads the arguments about to leave your process and answers what may happen to them: let it run, ask a human, or stop it cold. Four rules do the work, and each one is a test in this repository before it is a sentence here.</p>
    <dl className="ct-rules">
      <div><dt>Exact means exact</dt><dd>Changed arguments need a new approval.</dd></div>
      <div><dt>Once stays once</dt><dd>Same effect key, shared store, no repeat.</dd></div>
      <div><dt>Unknown means wait</dt><dd>Confirm the outcome before retrying.</dd></div>
      <div><dt>Every answer is kept</dt><dd>Requests, decisions and results, refusals included.</dd></div>
    </dl>
  </div>

<section className="ct-section" id="use-it" aria-labelledby="ct-steps">
  <div className="ct-wrap ct-prose">
    <h2 id="ct-steps">Use it in three steps</h2>
    <p>The animation above is this section, recorded against the real library: one policy file, two short programs, four commands, nothing staged.</p>

    <h3>1. Install it.</h3>

```bash
pip install ctrlrun
```

    <h3>2. Write down what the agent may do.</h3>
    <p>One file, <code>ctrlrun.yaml</code>. Amounts are integer minor units, so <code>50000</code> is €500. Both ends of every band are bound, because an upper bound alone lets a negative amount through, and a refund of a negative amount is a charge. Anything not listed is denied; there is no default-allow.</p>

```yaml
schema: ctrlrun.policy/v2

actions:
  stripe.refund:
    effect: "refund:{payment_id}"
    rules:
      - when: { amount_gte: 0, amount_lte: 50000 }
        decision: allow      # up to €500: the agent acts alone
      - when: { amount_gte: 0, amount_lte: 1000000 }
        decision: approve    # up to €10,000: a human decides
      - decision: deny       # above that: never
```

    <h3>3. Wrap the call that has the consequence.</h3>
    <p>The decorator names the action, the effect key names the consequence it has in the world, and the context names who is acting. <code>stripe</code> here is a stand-in that records calls instead of making them.</p>

```python
import ctrlrun


@ctrlrun.protect("stripe.refund", effect="refund:{payment_id}")
def refund(payment_id: str, amount: int) -> dict:
    return stripe.refund(payment_id, amount)


with ctrlrun.context(agent="support-agent"):
    refund(payment_id="txn_1", amount=50_000)      # €500   -> succeeded
    refund(payment_id="txn_2", amount=500_000)     # €5,000 -> ApprovalRequired, a human decides
```

    <p>The €500 refund runs on its own. The €5,000 one stops and names the request a human answers.</p>
    <p><strong>A human answers from the shell.</strong> The grant names the hash of the exact action the human read, and when it lapses.</p>

```console
$ ctrlrun approve "$(cat request_id.txt)"
granted apr_63e80076f2cccfee52b17491a4b2e125 for sha256:22ec1c39…6af752
expires 2026-09-13T20:10:11.367Z
```

    <p><strong>The agent presents it, then tries to spend it on something else.</strong> The first call is exactly what the human approved, and it runs. The second is the same approval with one digit changed, and it matches nothing.</p>

```console
€5,000 with the approval -> succeeded
€9,000 on that same approval -> refused
calls that reached the provider: 1 (the €9,000 never left)
```

    <p>Every attempt, refusals included, left a receipt, and <code>ctrlrun receipts</code> lists them. That is the whole integration: a policy file, a decorator, a context, and <code>with_approval</code> to present a grant. Money is the example, not the scope: the same policy language reads <code>role_in</code> or <code>replicas_lte</code> as easily as <code>amount_lte</code>.</p>

<section className="ct-section" aria-labelledby="ct-ways">
  <div className="ct-wrap ct-prose">
    <h2 id="ct-ways">Three ways to use it</h2>
    <p><strong>You probably do not need an adapter.</strong> <code>@protect</code> covers anything running in this process: a raw model call, a LangChain tool, a hand-rolled loop, a cron job. The gateway covers anything that reaches its tools over MCP, in any language.</p>
    <table className="ct-table">
      <thead><tr><th>You have</th><th>Use</th><th>Needs</th></tr></thead>
      <tbody>
        <tr><td>Python in this process</td><td>the <code>@protect</code> decorator, shown above</td><td>nothing beyond <code>pip install ctrlrun</code></td></tr>
        <tr><td>Tools behind an MCP server, in any language</td><td>the gateway: <code>pip install "ctrlrun[gateway]"</code></td><td>one command, no change to agent or server code</td></tr>
        <tr><td>A framework with its own approval interrupt</td><td>an adapter</td><td>the framework to have a human-in-the-loop primitive</td></tr>
      </tbody>
    </table>
    <p><strong>It works with agents you can and can't modify.</strong> WhatsApp, Slack and Teams bots, ChatGPT, Cursor, Codex, OpenAI Agents: any AI agent you have. CTRLRun checks the action, not the agent, so if the agent acts through a tool server or an API you run, the action is checked, and the agent is not rebuilt, redeployed or told. <a href="/docs/agents-you-cant-modify">Agents you can't modify</a> says where the boundary goes for each kind.</p>

<section className="ct-section" id="verify" aria-labelledby="ct-verify">
  <div className="ct-wrap ct-prose">
    <h2 id="ct-verify">Prove it in your own setup</h2>
    <p>State lives in SQLite by default, a file with no server and no ops, and the reservation holds across processes rather than merely across threads. Point it at Postgres when more than one host writes: one URL, the same guarantees graded by the same suite. Prove it in your own setup with <code>ctrlrun verify</code>, which runs the kernel's own failure scenarios against <em>your</em> policy in a scratch store. It reaches no network.</p>

```console
$ ctrlrun verify
CTRLRun verify — ctrlrun 0.9.0, catalogue ctrlrun.guarantees/v6
policy     ctrlrun.yaml (ctrlrun.policy/v2, mode: enforce)
store      sqlite, scratch (created and destroyed for this run)

G1   mutated approval refused         PASS  stripe.refund
G2   replayed approval refused        PASS  stripe.refund
G3   duplicate effect refused         PASS  stripe.refund
G4   one winner under concurrency     PASS  stripe.refund (8 processes)
G5   ambiguous blocks a blind retry   PASS  stripe.refund
G6   unknown action refused           PASS
G7   no principal refused             PASS  stripe.refund
G10  unknown exception is ambiguous   PASS  stripe.refund
G11  an altered receipt is detected   PASS  stripe.refund
…    24 guarantees graded in the full run
```
